# PACT Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add bounded canonical ledger scans, a disposable validated SQLite index, deterministic causal log/query commands, cursors, and explicit local-replica completeness diagnostics without changing canonical history semantics.

**Status:** Contract approved by Doctor Biz on 2026-08-24. Implementation starts from commit `a6c6c14` on `wip/phase-2-dag-index-query`.

**Architecture:** `internal/ledger` owns one bounded, context-aware canonical scan and all graph meaning. `internal/index` alone owns SQLite, builds a derived snapshot from that scan, validates the snapshot before every indexed read, and resolves selected rows back through canonical ledger bytes. `cmd/pact` remains an argument, exit-code, and output adapter. `.pact/objects/` stays the only source of history.

**Tech Stack:** Go 1.26, Go standard library, `golang.org/x/text`, `modernc.org/sqlite v1.57.0`, SQLite schema v1, shell product gate, Python reference suite through `uv`.

## Global Constraints

- The exact product contract is [the approved Phase 2 design](../../plans/phase-2/design.md). If this execution plan and that design differ, stop and fix this plan; do not improvise a third contract.
- Preserve every existing Phase 0/1 canonical byte, object ID, event ref, signature rule, command, JSON field, and exit meaning. New verify fields are additive. `show` never needs the index.
- Apply `pact/resource-limits/phase2-v1` before large allocation where encoded counts allow it and again while streaming. Exact-bound inputs pass; the first over-bound observation returns `LimitError` without continuing for an exact larger count.
- `supersedes` is a checked and indexed reference. It never creates a causal scheduling edge. Only parents and resolved `caused_by` refs create signed causal order.
- SQLite stores no payload, evidence, signature, public key, private data, trust state, authorization state, or canonical path. SQL and the SQLite driver stay in `internal/index`.
- Rebuild holds the existing store lock exclusively. Status, log, and query hold the same lock shared from source fingerprinting through canonical row resolution.
- Production behavior follows strict RED, smallest GREEN, then refactor. Each task gets an implementation report, an independent review package, a clean review, a focused commit, and a line in `.superpowers/sdd/progress.md` before the next task starts.
- Use `env -u GOROOT mise exec -- ...` for Go and Git hooks on this machine. Never bypass hooks.
- Hand-written source files that support comments start with two `ABOUTME:` lines. Do not change generated, vendored, canonical object, or bundled reference files.
- Do not merge setup CLI work, start Phase 3, add auto-rebuild, add raw SQL, or add a compatibility/migration path.

## Execution and review protocol

For every task:

1. Record `base=$(git rev-parse HEAD)` in the task brief.
2. Dispatch one fresh implementer with only the approved design, this task, relevant files, and the TDD rule.
3. Require the implementer to record the exact RED command and why it failed before production code.
4. Run the task's GREEN commands locally, then generate a review package for `base..HEAD` or the uncommitted task diff.
5. Dispatch a fresh reviewer. Fix all Critical and Important findings, and all Minor findings that are in scope. Repeat review until clean.
6. Run focused checks, inspect `git status`, stage exact paths, and commit with the task's conventional commit message.
7. Append task, commit, tests, review result, and next task to `.superpowers/sdd/progress.md`.
