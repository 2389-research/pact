# development/v1 contract

`RecordInput` is the caller object. `operation_id`, `namespace`, `subject`, and
`source` belong to that object once. Each `InputEvent` supplies only `local_id`,
`type`, `payload`, `evidence`, `caused_by`, and `supersedes`. Payloads contain the
caller fields below; callers do not supply `operation_id` or `source` inside them.
The validator will inject those two facts into each signed payload, and supply
`kind`, `subject`, and the exact bundled schema digest on the ledger envelope.
The recorder will own its request digest in batch metadata.

`EventDefinitions()` returns fresh closed field definitions and conditional
schema rules. `CheckOutcomes()`, `ReviewVerdicts()`, `FindingSeverities()`, and
`AcceptanceDecisions()` own the enum lists. Runtime validation must reuse these
field/enum definitions and the core ledger normalizer; this package does not
interpret arbitrary schemas or validate caller input yet.

All signed payloads require `operation_id` and `source` and allow an optional
nonempty `summary`. A source requires a repository label and full lowercase Git
SHA-1 (40 characters) or SHA-256 (64 characters) revision. Source identity does
not prove execution or ownership of the repository label.

| Type / envelope kind | Caller payload fields |
| --- | --- |
| `dev.check.executed` / `observation` | Required `name`, `command` (nonempty string argument array), `outcome`, `evidence_indexes`; optional `exit_code` (integer), `signal`, `interruption`, `coverage` (`completed`, `total`, both nonnegative integers) |
| `dev.review.completed` / `observation` | Required `verdict`, `findings`, `resolves`, `evidence_indexes` |
| `dev.acceptance.recorded` / `decision` | Required `decision` (`accepted` or `rejected`), `rationale`, `policy_ref`, nonempty `check_refs`, nonempty `review_refs`, `evidence_indexes` |
| `dev.next_action.recorded` / `action` | Required `actor`, `action`, `blocking_event_refs`, `blocking_findings`, `evidence_indexes` |

A finding has `id`, `severity`, `summary`, and `evidence_indexes`. A resolution
has `review_event_ref`, `finding_id`, `correction_source`, and at least one
`evidence_indexes` entry. A blocking finding has only `review_event_ref` and
`finding_id`. Every object is closed. Collections remain arrays even when empty.
Evidence indexes are distinct nonnegative integers into the containing event's
ordinary ledger evidence array. The core ledger owns evidence-entry fields.

Passed checks require zero exit; failed checks require a positive normal exit.
Neither carries interruption fields. Interrupted checks require an observed
signal, interruption description, or nonzero interruption exit code (including a
negative process API result). Unknown
and not-run checks carry no observed exit or interruption. Coverage does not
change outcome. A `changes_required` review requires at least one finding.

References accept immutable `pact:event:sha256:...#local-id` and core `local:id`
forms. Local payload refs resolve relative to the containing commit, as local
envelope refs already do; they are not globally stable IDs on their own. The
core ledger does not resolve refs *inside payloads*. The profile projector must
do that. A causal or supersedes edge never supplies finding-resolution meaning.

JSON Schema checks shape and conditional fields. It cannot enforce unique
finding IDs by one field, evidence-index bounds, completed <= total, actual Git
commit existence, resolution validity, reference reachability, known policy
identity, authority, or acceptance support. Later validation, evidence, and
projection tasks own those checks. The policy artifact is named local
configuration; it is not a registered policy or an organizational approval.

Regenerate the five supported artifacts and their golden digest manifest with:

```sh
env -u GOROOT mise exec -- go generate ./internal/development
```

`ProfileArtifacts()` returns the four exact schema byte sequences and named
`local-policy.json` bytes. The separate `digests.json` manifest pins those bytes;
it is not itself a supported payload schema. Tests compare generated bytes and
SHA-256 digests with published artifacts and invoke the reference environment's
JSON Schema oracle on the public corpus. Deliberate contract changes must review
both bytes and digests; generator success alone does not authorize a new profile.

## Runtime validation

Use these read-only interfaces before opening a signing key:

```go
DecodeInput(context.Context, []byte) (RecordInput, error)
ValidateInput(context.Context, RecordInput) (ledger.EventBatch, error)
ValidatePayload(context.Context, string, string, map[string]any, int) error
```

`DecodeInput` requires one record object, rejects duplicate/extra fields, and
uses the strict canonical parser. `ValidateInput` applies shared field/enum
shapes and local semantic checks, injects operation/source and fixed envelope
facts, then calls `ledger.NormalizeEventBatchContext`. It returns fresh normalized
data and never changes caller maps. Programmatic payload values must use the
core's JSON types (`map[string]any`, `[]any`, strings, booleans, integers, or
`json.Number`); floats and invalid UTF-8 fail rather than being repaired by a
standard JSON encoding round trip. Required collections must be arrays.

`ValidatePayload` arguments are context, event type, schema digest, signed
payload, and containing event evidence count. It accepts only the exact bundled
type/digest pairing and validates the already-injected signed payload. Unknown
raw domains and unsupported schema identities return `unsupported_type` or
`unsupported_schema`; raw ledger admission and history remain generic and
unchecked by this profile. This function neither normalizes an envelope nor
claims secret scanning of raw history. `ValidateInput` retains core secret and
envelope checks; it never duplicates the core scanner.

`ValidationError` exposes `Path` and `Category`. Its bounded message never
quotes caller contents or unknown field names. `errors.Is` preserves core error
identity (including `ledger.ErrSecretSafety`) through `Unwrap`; cancellation
returns the context error. Callers should render the validation error itself,
not its underlying core cause, which may include input-dependent diagnostics.

Local validation checks evidence-index bounds, unique finding IDs, coverage
arithmetic, and outcome/observation consistency. It does not read Git or proof
bytes, prove source existence, resolve payload references, establish correction
or policy validity, or determine acceptance. Those require evidence/history
context in later tasks. A syntactically valid local payload ref may still name
missing history. Command argument strings remain reported data and never run.

## Local projection

`Project(ctx, store, ProjectRequest)` returns `WorkState` for an explicit
namespace, subject and full source revision. A nil frontier captures the namespace
heads once; an explicit empty frontier selects no history. Frontier entries are
unique commit IDs in that namespace. Deriving current heads refuses any invalid
canonical object because its work scope cannot be safely recovered. An explicit
valid cut can still exclude unrelated malformed objects. The result sorts identities for stable
serialization, never to select a semantic winner.

The projector holds one store read lock around a bounded `ledger.Scan` and
bounded canonical payload reads. It verifies selected bytes against scanned IDs,
then projects the closure of parents and `caused_by` dependencies, retaining every
event in each selected commit. Missing or invalid causal dependencies refuse the
projection. The bounded inventory still covers the local store: exceeding core
scan limits can refuse an old cut, but newer events never enter that cut's state.
Evidence reads happen after snapshot capture through one `evidence.ResolveAll`
budget. No index, trust, canonical object, or evidence file is written.

Checks and valid recorded decisions are scoped to the requested revision.
Findings and declared next actions include the selected work's whole reachable
history; next actions are never inferred. Invalid or unknown relevant events are
identified in `completeness.issues` and cannot support acceptance. Findings keep
their original review/finding IDs. Only an approved, authorized review that
observes the original finding, names its own exact source as the correction, and
selects durable matching proof resolves it. A decision must observe a valid
resolution before that resolution can support the decision.

Causally maximal exact-revision decisions determine current support. All recorded
decisions remain visible. Concurrent accepted/rejected maxima yield `unresolved`;
causal replacement is determined from parent and cause links, never `supersedes`,
timestamps, event-array order, or hash order. Missing decisions produce
`not_recorded`; rejected decisions remain recorded with `unsupported` support.
An accepted decision requires nonempty durable matching evidence selections for
itself and each selected passed check and approved review, exact source label and
revision matches, the same namespace/subject, known local root authorization, and
causal observation. No open Critical/Important finding or relevant unchecked,
invalid, unresolved, unknown-authority, or unmatched selected evidence can coexist
with `supported`. Minor findings stay visible. Unselected checks do not override
the decision's declared proof selection.

`profile_digest` hashes the canonical object mapping every `ProfileArtifacts()`
filename (including policy) to its exact byte digest. `policy_digest` names the
unchanged `local-policy.json` bytes. `projector_identity.version` is
`development/projector/v1`; its digest hashes the canonical filename-to-byte-digest
map for the embedded `project.go`, `project_types.go`, and `policy.go` source files.
This identifies this projection algorithm, separately from the inspected work's
source. It is not a full binary or dependency build attestation. The core ledger,
validator, resolver, toolchain, and evidence availability remain part of the
execution environment. Embedded identity is mandatory; no unknown-identity
fallback can produce support.

Output collections are arrays, and full signed payloads accompany valid claims.
Evidence assessments contain locators and digests, never proof contents. There is
no wall-clock field in the deterministic result: observation time, if recorded by
a caller, is separate metadata. Caller-supplied source identity and hashed proof
do not establish that a process ran or that a repository label is owned. Local
root authorization does not establish reviewer independence, organizational
approval, global completeness, or official checkpoint acceptance.

The projection applies the core bounded inventory and evidence budgets and adds
a one-million-step causal traversal budget (`projection_causal_work`). A limit or
cancellation returns an error without a partial positive result. Output byte
budgets belong to the later brief adapter. The compiled test driver under
`testdata/projectdriver` is a test executable, not a public CLI command.
